## 整理原则

- `doc/文档导航.md` 按使用、开发、业务模块、架构决策和历史证据提供入口；专项在 `doc/plans/计划索引.md` 按主题查找。
- 模块保存当前职责、源码入口与关键边界；专项只保留独有设计、实际证据、未完成项和回退，不并列保存重复的执行步骤。
- 下列旧文先迁移仍有价值的内容、改完现行引用，再删除；旧结论注明原记录日期，不当作当前验收结果。
- 保留武器、本集资产、S3 后续阶段、真实厂商／桌面验收、各版发布证据，以及安全规范与 ADR。
- 不修改 README、业务源码、依赖、权限、用户素材和冻结的 `doc/history/`；冻结历史中的旧路径仍按当时记录保留，可从 Git 恢复。
- 根目录和旧 `docs/plans/` 的两组三份过程记录已检查：无现行入链、无本轮改动；独有安全边界与未完成项已有模块／冻结归档承接。外部工具上下文、AGENTS、Hindsight 与发布用 `.release-notes.md` 不在清理范围。
