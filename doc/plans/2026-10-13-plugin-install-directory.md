# 插件安装目录调整

## 目标与边界

- 桌面插件的原生存储由 `{appLocalData}/plugin-private` 改为 `{可执行文件所在目录}/Plugin`，开发环境同样以实际可执行文件为准。
- 注册表、源码 revision、UI 产物、声明资源、插件偏好与后续运行时工作区统一使用新根目录；IndexedDB 安装记录保持既有职责。
- 旧原生数据首次使用时迁移；已有新目录不覆盖、不合并。迁移失败保留旧数据，并明确报错，不回退旧目录执行。
- Windows 安装在任意盘符或受保护的 `Program Files` 时，仍固定使用安装旁 `Plugin`，不切换到 AppData，不依靠长期以管理员身份运行主应用。
- 新、旧和迁移暂存目录均维持 fs scope、asset scope 与通用路径命令的私有目录保护；目录授权不扩大插件权限或放宽 capability。

## 实施步骤

1. 修改 `src-tauri/src/plugins/registry.rs` 的目录定位与路径保护，固定使用可执行文件旁的 `Plugin`；拒绝符号链接、Windows 重解析点和非目录目标。
2. 复用既有注册表/快照布局迁移持久化数据，在安装目录内暂存后原子发布；只复制注册表及其备份、`revisions`、`ui-revisions` 与 `settings`，不迁移旧窗口 profile 或媒体任务。
3. 保留旧数据作为迁移备份；源码、UI、资源的摘要继续由现有执行/读取流程复核，损坏注册表沿用现有显式修复入口。
4. 在原生注册表测试中补充迁移内容、已有目录保护、失败重试与不安全路径回归；同步插件开发规范。

## Windows 目录授权补齐（2026-10-25）

1. 只在用户显式安装、更新、启用插件时，以普通权限实际探测目录创建与文件写入。只有 `PermissionDenied` 提供原生“授权创建插件目录”确认；路径无效、磁盘及其他 I/O 故障直接返回对应的脱敏类别与代码，不伪装成权限问题，不输出真实本地绝对路径。
2. 确认后通过 Windows `runas` 启动同一可执行文件的固定辅助模式。该模式在 Tauri、ONNX 与插件加载前分流，只能准备可执行文件旁的 `Plugin` 及固定 `Plugin.installing` 暂存区，并向原请求用户 SID 授予 `Plugin` 及必要子项的 `Modify`；UAC 使用其他管理员凭据时仍授权原用户。请求绑定原进程 PID、创建时间和同一 EXE，不接受路径、SID、脚本或任意命令。不向 `Everyone` 或父安装目录授予写权限，不读取注册表或插件源码正文，不运行插件。
3. 辅助进程准备新根时采用同卷暂存和原子发布，并保留 `.permissions-prepared` 标记。普通权限主进程继续旧数据迁移，成功后才完成标记；无旧数据也显式完成初始化。标记未完成期间，所有插件读取与执行入口都失败关闭，不把管理员刚创建的空目录当作已迁移数据。已有实际插件数据不覆盖、不合并，旧目录保留备份，窗口 profile、媒体任务和运行时授权不迁移。
4. 正常只读及后台调用不自动请求 UAC；未完成初始化只允许用户显式操作推进。设置页启用通过可选 `requestDirectoryAccess` 请求授权，自动激活与安装失败补偿不申请目录权限，避免取消后再次弹窗。并发安装串行准备目录；超时保留提升进程句柄，未确认结束前不启动另一个提升操作。取消、超时或准备失败明确结束本次操作，不循环提示。
5. 已有数据的 ACL 修复保留原权限，按最多 32 层、16384 项有界检查；固定全部路径句柄后逐项处理，不向未校验子项自动传播。重解析点及文件硬链接拒绝授权，原生插件信任确认和摘要复核不变。源目录读取错误不触发提权；目标 ACL 存在明确拒绝或安全策略仍阻止写入时，普通用户复查失败并停止，不继续扩大权限。

原生辅助入口在 `src-tauri/src/plugins/install_permissions.rs`，目录预检和迁移在 `registry.rs`，显式启用标记在 `src/store/store.plugins.ts`。跨账户身份查询若被拒绝，提升辅助进程只针对已指定 PID 临时启用自身 `SeDebugPrivilege` 一次重试，查询结束后、任何路径解析或 ACL 操作前恢复原状态；无法恢复即终止，不扩大目标进程访问权、不读取进程内存，也不以管理员 SID 兜底。

## 用户验收

前置：使用 Windows Tauri 桌面端和独立测试安装，主应用以普通用户运行；准备普通可写目录与 `E:\Program Files` 等受保护目录两种安装位置。升级前备份一个已安装插件及其非敏感偏好；保留可用于 UAC 的管理员账户。涉及目录、ACL 或迁移数据的操作只针对独立测试安装和备份。

1. 在普通可写位置安装、更新、停用/启用并重启：不弹 UAC；新 revision 和偏好仅写入安装旁 `Plugin`，卸载后重启不重新出现。旧插件可执行并打开内嵌/独立 UI，偏好保留。
2. 将独立测试应用安装到 `E:\Program Files` 等普通用户不可写的位置，显式安装插件：先显示目录授权确认，接受 UAC 后普通权限主进程继续安装。核对仅 `Plugin` 及必要的私有暂存子项对原用户获得所需权限，父安装目录未被放权，主应用与插件未变成管理员运行。
3. 分别取消目录确认、取消 UAC、让辅助进程超时：当前操作清楚结束，失败补偿不再弹窗，不留下可执行的半完成插件。使用另一个管理员账户通过 UAC，原普通用户仍可继续安装与重启使用；管理员账户不能替代原用户 SID。再次显式启用已停用插件仍可请求授权。
4. 从旧 `{appLocalData}/plugin-private` 迁移已安装插件及偏好：权限准备后继续完成数据迁移，旧目录仍在。人为制造迁移失败后，`.permissions-prepared` 未完成时读取与执行应被拒绝；排除故障并显式重试后数据完整。无旧数据的新安装也能完成初始化。
5. 已有实际 `Plugin` 时修改旧备份数据：重启仍使用现有新目录，不覆盖、不合并。检查已有数据、偏好和摘要在授权及失败重试后不丢失；正常只读查询与后台任务不自动弹 UAC。
6. 测试无效安装路径、同名普通文件、符号链接、目录联接、迁移数据中的链接，以及已有插件子目录禁止写入的 ACL：保留对应错误，禁止跟随链接或向安装目录以外放权；修复环境后可显式重试。其他 I/O 故障不触发 UAC，错误不泄露本机绝对路径。
7. 原生注册表损坏仍提供既有显式修复入口；普通文件 API、asset URL 与通用递归/归档命令拒绝新旧私有目录及适用祖先。回归可信 Python、双摘要和独立 WebView 边界，目录授权不能替代插件原生信任确认。

原生检查（用户执行，目录 `src-tauri`）：

```powershell
cargo test --lib plugin_registry::tests --no-default-features --features tauri-channel-tests
cargo test --lib plugin_install_permissions::tests --no-default-features --features tauri-channel-tests
cargo check --lib --locked
```

前端回归（用户执行，仓库根目录）：`npx vitest run tests/store/plugins.test.ts`。

## 回滚

停止应用后回退相关源码。回退代码不会自动撤销已授予 `Plugin`、`Plugin.installing` 的目录 ACL，也不会自动合并新旧数据；若需撤销权限，须在独立确认和备份后由用户检查并处理准确的目录与 SID，不能修改父安装目录或给其他用户放权。

迁移保留的旧目录是迁移时备份，不能代表新版本安装/更新/卸载后的最新状态；需要保留后续数据时，先备份新目录，再按所回退版本的存储合同处理持久化子目录。不要手动合并两份注册表、修改摘要，或清除尚未完成迁移的标记来绕过读取/执行门控。
