# 素材使用位置与失效修复实施计划

**目标**：文件与创作卡片共用使用位置/删除影响查询；失效文件和登记目录支持预览、验证及显式重连。

**架构**：查询持久化全项目、剧集资产、全局资产、历史及对话，并叠加当前画布未保存引用；只按稳定身份和精确媒体/引用协议匹配。修复通过原子媒体迁移日志和 Store Action 提交，保留旧路径撤销保护，不修改路径 ACL。

**技术**：TypeScript、Zustand、IndexedDB、Tauri fs/dialog、既有固定块内容摘要与媒体迁移日志。

## 实施顺序

1. 在 `types/assetUsage.ts` 定义共享查询目标及结果；新增 `assetUsageService.ts` 和 `assets/AssetUsageDialog.tsx`。读取错误阻止删除；定位复用项目切换与 `canvas-focus-node`。
2. 新增 `fs/assetRepair.ts`，预览明确选择的文件/目录。缺失与读取失败分别呈现；有摘要严格核对，无摘要只标元数据匹配并逐项确认，多匹配不猜测。
3. 在 IndexedDB 索引和媒体迁移日志增加窄批量接口，提交时复核原索引及目标占用。项目 slice 提供修复 Action，同步当前 Store 与历史，不接受迟到状态覆写。
4. 文件菜单、目录导航及存储健康接入统一弹窗，健康扫描使用真实登记目录；创作卡片入口由主任务接入。
5. 补身份隔离、读取失败、修复歧义与取消回归，仅写用例，不执行。

## 验收边界

- 先查看同文件在不同项目/分集、角色参考图/声音/动作中的引用，再定位真实节点；同名不同 ID 不串联。
- 删除前展示实际影响；读取失败或扫描期间引用变化不直接删除。
- 选择移动后的文件夹预览逐项结果；损坏、类型不符、摘要不符及权限错误不能重连。
- 无旧摘要明确显示仅元数据匹配，未逐项确认的不提交；部分匹配保留待修复项。
- 修复后关闭重开、撤销/重做、重命名、共享剧集媒体和旧路径再分配保持稳定身份。

状态：已实现，待用户验收。未运行功能测试、类型检查、构建或桌面验收；提交时由仓库钩子执行改动文件的定向 ESLint。

实现边界：查询包含持久化项目/剧集资产、全局资产、生成及撤销历史、对话/任务、剪辑工程、工作流/预设和图片信息关联；读取错误阻止删除。修复每批最多 500 个异常项，单次最多检查 10,000 个索引，达到上限明确标记其余状态未知。原文件无内容摘要时仅按类型、大小和修改时间预览，必须逐项确认；新摘要随修复保存。修复同步精确 `@asset` 路径 token 及稳定媒体身份，普通正文不改；事务成功后不因视图取消撤回修复。受控复制失败可能留下未引用副本，用户原件不删除。
