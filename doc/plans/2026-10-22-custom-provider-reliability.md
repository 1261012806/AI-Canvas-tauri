# 自定义接口配置可靠性

日期：2026-10-22。状态：源码及回归用例已实现，待用户桌面验收；未运行测试、lint、类型检查、构建或付费调用。

## 目标和边界

修正自定义模型试跑、草稿切换、配置导入与状态提示，避免占位素材引发错误、丢失尚未提交的草稿、误报调用成功或重复提交生成。

不新增依赖、原生权限、数据库字段或凭据存储；不改变内置厂商调用合同。可选参数允许未声明，不猜接口路径或模型能力。本计划覆盖普通自定义模型连接，不扩展工作流 API 的父层草稿保存机制。

## 实现

1. `ModelProtocolEditor.tsx` / `modelProtocolTestRun.ts`：本地预览和真实试跑使用独立变量；视频按文生、首尾帧、多参考三种场景准备真实公网素材。视频变量动态复用节点的共享构造器和模型能力，不混入隐藏场景的素材。示例地址、错误数值在提交前阻止。
2. `modelProtocolTestSession.ts`：有界进程内会话按连接、模型和完整 Base URL 绑定，保存任务 ID、原类别及不含 Key 的查询描述。暂停、查询超时和网络异常保留原任务；重新查询只调用原查询合同。上游明确失败不可续，提交未拿到 ID 时保留不确定状态并禁止直接重投。异步结果通过类型校验后才清理。
3. `ProviderConnectionDialog.tsx` / `ProviderModelSection.tsx`：保护未同步协议原文及自定义连接未保存修改；取消放弃时保留面板和选择。保存期间防止重复提交和编辑。新自定义连接保存时沿用试跑身份，已保存连接关闭重开可续查。尚未保存又明确放弃连接时不承诺恢复该连接；应用刷新或重启也不恢复本批试跑记录。
4. `modelCapabilityValidation.ts`：保存和试跑共用结果映射类别检查；真实文本必须非空，媒体必须为有效无凭据 HTTP(S) URL，或 MIME 符合类别的非空 data URL。不根据 URL 后缀猜媒体类型，不把请求成功等同于结果可交付。
5. `providerConnectionTransfer.ts` / `ApiKeySettings.tsx`：导入错误逐模型列出列表、索引、字段路径及脱敏原因；任何错误阻止整批写入，不静默丢协议。Key 继续剥离，未知预设和非法协议失败关闭。
6. `apiKeySettingsUtils.ts`：自定义连接区分 Key 填写与协议本地状态；“本地校验通过”不代表实际调用已验证，真实结果只在对应验证/试跑入口展示。

## 桌面验收（待用户执行）

前置条件：Tauri 桌面开发版载入本批源码；准备一份已有自定义连接及一个有异步协议的视频模型。真实试跑由用户决定是否执行并承担厂商计费。

1. 打开设置 → API Key → 自定义连接 → 模型调用协议。分别编辑本地预览和真实试跑 JSON，预期两者互不覆盖；视频默认不带假链接或参考素材，明确声明的默认参数可见，未声明参数留空。
2. 在首尾帧场景填写图片，在多参考场景填写图片/视频/音频，再来回切换。预期只准备当前场景的素材，不混发；缺少素材、使用示例网址或时长填字符串应在本地提示，不提交请求。
3. 在 JSON 中暂时删掉逗号，切换表单，预期原文保留并提示；修正后可切换。表单里写坏请求体或清空必填路径，尝试切模型、参数面板、分类、取消勾选、应用模板或关闭连接；选“继续编辑”后所有内容及选择保持。确认放弃后才导航。没有修改直接关闭不提示，保存成功不提示放弃。
4. 导入含非法路径、未知预设或“视频只返回文本”的连接文件，预期列出具体模型与字段，连接数和已保存配置不变；修复后整体导入成功，Key 为空。未声明可选能力不应导致拒绝导入。
5. 填写 Key 后列表显示“Key 已填写”；未配置视频协议显示“协议待配置”，无效配置显示“配置需修正”；合法配置显示本地校验状态和未验证调用的说明。只读连接验证不能当作模型生成已验证。
6. 可选真实异步验收：点击一次试跑，取得 ID 后暂停，关闭设置再打开并继续查询，预期 ID 不变、无第二次生成提交，完成后可复制结果 URL。新建连接应先保存；修改地址或 Key 应停止旧界面的等待，切回原连接仍可处理其任务。厂商明确失败保持错误，未拿到 ID 的取消提示状态不确定。
7. 可选异常验收：查询超时/断网、结果字段误指文本、HTTP 200 返回 JSON 二进制或错误 MIME 时不显示成功；已有任务 ID 保留。合法签名 URL 即使没有文件后缀也应接受。检查深浅主题、窄窗口及键盘操作，旧图片、文本、音频模型保存继续可用。

回归入口：本批 `modelProtocolTestRun`、`modelProtocolEditorInteractions`、`modelProtocolTestSession`、`providerConnectionDraftGuard`、`providerConnectionTransfer`、`providerConnectionModels`、`apiKeySettings`、`apiKeyDeletionPersistence` 等测试文件；均已补用例，未执行。用户需要时可在仓库根目录运行对应的 `npx vitest run <测试文件>`。
